# 0004 quota-aware model routing
## Status: accepted (accepted-by user in chat 2026-11-07 "Approve both"; approves routing + UI tracks to implementation plans)
## Context: Two $10 OpenRouter accounts (~2,000 free req/day pooled at 20 RPM each) sit configured but unused; Go-plan quota is the binding constraint. Research (2026-11-07, 4 cited researcher reports): best free agentic-coding picks are cohere/north-mini-code:free (tools, stable, no training) with recursive/flint-v1.0:free fallback and paid openai/gpt-oss-120b ($0.03/1M) safety net; reviewer/planner nvidia/nemotron-3-ultra-550b-a55b:free (reasoning, 1M ctx, trains on prompts — no customer code); summarizer google/gemma-4-31b-it:free else dots-studio/dots-3-note-preview:free. Each :free endpoint has exactly ONE provider (no same-model fallback; Flint 0/3 Nov 3). OpenCode has per-agent model pins + inheritance but NO quota-aware/automatic fallback (transport retry + disabled-model fallback only). Avoid: poolside/laguna (expired 2026-10-31), inkling (harness-only, expiring), lfm-2.5, safety classifier.
## Decision: (1) Two provider entries openrouter + openrouter-b with separate keys via {env:} injection; orchestrator alternates accounts round-robin, tracked in progress ledger. (2) Static per-agent free-first defaults (implementer north-mini-code; reviewer/planner nemotron-3-ultra; summarizer gemma-4) + orchestrator tier override by task weight. (3) Fallback chains per role on 429/provider-error; paid fallback ONLY with envelope pre-authorized micro-spend cap, else stop+escalate (spend stays ALWAYS-human). (4) Privacy routing: customer code only to no-train endpoints; NVIDIA endpoints non-sensitive only; never send secrets anywhere free. (5) Maintained denylist + periodic catalog re-probe procedure (GET /api/v1/models + expiration_date), documented not automated.
## Goal: Go-plan usage drops with zero task-quality regressions (eval-gated); 429s route around outages without human keystrokes inside the envelope.
## Non-goals: replacing Go primaries; auto-spend; per-token dashboard (Console covers it); modifying OpenCode.
## Alternatives: manual picker (user chose auto); single account (halves quota, no redundancy); paid-first (defeats goal); plugin runtime routing (no model-selection hook exists).
## Trade-offs: free quality variance + outages (chains + Go fallback); orchestrator complexity (ledger-tracked alternation); latency; prompt-training exposure (traffic rules).
## Trace: quotas→chains+alternation→eval probes; models→per-agent pins→contract tests; privacy→traffic rules→review checklist.
## Review findings: requirements (quota math ~2000/day supports ~10-20 sessions/day/account); failure modes (Flint outage, Gemma 429 exhaustion, single-provider fragility); operability (ledger shows which model/account did what). No open questions blocking plans.
## Leading indicators: Go-plan usage delta; fallback frequency; 429-escalation count; issues caught pre-implementation.
